# 信贷指标异常 · 证据工作台

一个面向信贷分析员的浏览器原型：导入按日期、渠道汇总的 CSV，检查数据质量，比较两期指标和每日趋势，引用计算证据，记录复核并生成 Markdown 报告。也可以直接使用三个合成场景体验。

在线体验：<https://cbb-cbb.github.io/credit-evidence-demo/>

**原 CSV 工作台的文件处理、指标计算和报告生成均在浏览器内完成，没有在线大模型调用。** 当前是个人探索原型，尚未以真实业务数据验证规则效果。

## 本地数据库与大模型版本（V3）

新增 [数据库分析页面](assistant.html)：从本机 SQLite 模拟贷款记录取数，计算可复算的指标和证据，再选择调用大模型解释，并将分析快照与复核保存到数据库。暂时拿不到真实业务表时，可以先用三个模拟场景跑通流程。

运行 `npm.cmd start` 后打开 <http://127.0.0.1:5174/assistant.html>。数据库首次自动创建，不需要安装数据库软件；大模型需在本地 `.env` 配置 API 地址、模型名和 API Key。未配置时仍可分析数据，不会显示虚构的模型回答。完整步骤和口径见 [DATABASE_LLM.md](DATABASE_LLM.md)。

## 三分钟体验

1. 打开“导入 CSV”，点击“载入示例 CSV”，按页面提示“校验并载入数据”。也可使用 [示例文件](examples/valid-channel.csv)。
2. 使用正常对比期 **2026-07-01 至 2026-07-04**、待分析期 **2026-07-05 至 2026-07-08**。
3. 先保持观察期确认框未勾选并运行：可以看统计事实，但系统暂停归因。示例中的观察期是合成假设，读完声明后可确认并再次运行；真实数据必须先自行核查。
4. 比较每日趋势、两期分子与分母、渠道占比和自身逾期率。示例的整体逾期率应从 **12% 变为 20%**，变化为 **+8 个百分点**；两个渠道自身逾期率保持不变。
5. 用证据编号写一条复核，例如哪条证据支持某个解释、还缺什么信息。再点击“生成分析报告”，复制或下载 Markdown；JSON 用于保留结构化分析记录。

继续试 [缺日期示例](examples/missing-days.csv) 和 [格式错误示例](examples/invalid-quality.csv)，看提示能否说明问题所在。三个原合成场景仍保留：渠道 C 放量、稳定对照、全渠道风险上升。

## 能处理什么

输入为 UTF-8 CSV，每行是一日一个渠道的聚合计数，包含以下四列：

```csv
date,channel,count,overdue
2026-07-01,常规渠道,900,90
2026-07-01,新渠道,100,30
```

`date` 是 YYYY-MM-DD；`count` 是放款笔数，`overdue` 是其中按统一定义标记为逾期的笔数。计数须为非负整数，逾期数不能大于放款数；日期与渠道组合不能重复。额外列不用于分析。单文件上限为 2 MiB、20,000 行、50 个渠道、366 天跨度。

**四列聚合数据无法证明 FPD30 观察期完整，也无法验证分母与逾期定义是否一致。** 界面上的勾选仅记录使用者声明。新导入数据必须单独核查，不能因为格式校验通过就视为业务数据合格。

| 检查结果 | 展示行为 | 应如何处理 |
| --- | --- | --- |
| 格式错误、重复记录、日期无效 | 列出问题，不载入为可分析数据 | 修复对应行后重新载入 |
| 窗口缺日期、缺渠道日记录或没有样本 | 拦截归因，不显示虚假的零逾期率 | 调整窗口或补齐数据；确实无放款时显式填 0 |
| 观察期未确认、任一期少于 100 笔、渠道新增或退出导致不可比 | 展示描述性统计，暂停归因并提示复核 | 核对观察期、补充样本或确认渠道口径 |
| 当前检查通过 | 展示透明规则产生的候选解释及证据编号 | 结合业务事实复核，不直接认定因果 |

100 笔是原型的教学门槛，不是统计显著性检验，也不保证样本充分。汇总逾期率按分母加权计算，不简单平均每日或各渠道的比率；新增、退出渠道的缺失率不会补成零。

## 从 V1 到 V2

| 原型阶段的问题 | V2 增加的能力 | 可核查结果 |
| --- | --- | --- |
| 只能切换预设合成场景 | 文件选择、CSV 粘贴编辑、格式及计数校验 | 可用自己提供的聚合数据，错误行有具体提示 |
| 看得到总结果，不易判断变化是否持续 | 每日趋势与可展开的每日计数 | 每个率可以用分子、分母复算 |
| 文件结构正确容易被误解为样本可用 | 观察期声明、样本量和渠道可比性检查 | 不满足条件时仅展示事实，暂停归因 |
| JSON 对分析复盘不够直观 | 中文 Markdown 报告 | 包含数据指纹、窗口、证据引用、复核和下一步 |
| 多份数据容易混淆复核上下文 | 以数据指纹和分析窗口区分记录 | 数据变更后不沿用另一份数据的复核 |

V1 根据实际体验改进的日期自由调整、缺数据前置提示和人工复核仍保留。原本地项目的 8 次工具调用与本 Demo 的 0 次归因规则执行不是同一机制，不能据此计算 Agent 的效率提升。

## 本地运行与检查

Node.js 24 或更新版本（使用内置 SQLite），无第三方 npm 依赖，无需 `npm install`：

```powershell
npm.cmd start
```

打开 <http://127.0.0.1:5174/>。JavaScript 模块需通过 HTTP 加载，不要直接双击 HTML。

```powershell
npm.cmd test
npm.cmd run check
```

V2 本地工程验收已完成：`npm test` 的 **117 项全部通过**（引擎 51 项、CSV 解析 58 项、报告 8 项），`npm run check` 的全部应用模块语法检查通过。浏览器已核对合成场景、实际文件与粘贴导入、质量拦截、趋势、报告预览和复核隔离；详细记录见 [EXPLORATION.md](EXPLORATION.md)。下载文件是否实际落盘尚未确认，页面保留复制导出文本的方式。

在线版本仍使用原链接，可通过页首“CSV 分析原型 · V2”识别本次迭代。以上为工程验收，用户个人的 V2 独立验收与讲解仍待完成。

## 贡献与文件入口

用户选择信贷异常场景，亲自完成原项目的三类案例操作，发现日期选择限制，并参与缺数据提示问题的复盘。V1、V2 及本地 V3 的代码、文档和自动化检查由 AI 辅助完成；用户独立验收和讲解需亲自完成。这里不把生成代码写成用户独立编程，也不把个人原型写成前公司的业务成果。

- `app.mjs` / `views.mjs` / `index.html` / `style.css`：导入、趋势、证据、复核与导出界面。
- `data-import.mjs`：CSV 解析、结构校验、归一化与数据指纹。
- `engine.mjs`：合成数据、窗口与样本检查、汇总和规则计算。
- `report.mjs`：基于计算结果生成中文 Markdown 报告。
- `database.mjs` / `llm.mjs` / `server.mjs`：本地数据库、可选模型接口与后台。
- `assistant.html` / `assistant.mjs` / `assistant.css`：数据库分析、模型解读、持久化复核与历史。
- `tests/` / `examples/`：自动化行为测试与可复算 CSV 样例。
- [METHODS.md](METHODS.md)：统计口径、阈值和数学分解。
- [EXPLORATION.md](EXPLORATION.md)：问题发现、取舍、验证与待完成事项。
- [PROVENANCE.md](PROVENANCE.md)：来源与 AI 协作说明。

CSV 页上传的文件只在当前页面处理，不发送到远程服务，刷新后需重新导入；该页复核只保存在当前浏览器。数据库页的分析与复核保存在本机 SQLite，点击模型解读时向配置的服务商发送合成汇总证据。报告不含原始 CSV 行或逐笔贷款，但包含数据集名称、汇总和复核文字。数据指纹用于区分版本，不是加密、签名或真实性认证。
