# 信贷指标异常 · 证据工作台

一个可以直接操作的个人产品探索作品：先检查数据是否可用，再比较证据，最后记录人工复核。需求来自对现有信贷异常诊断项目的实际体验，演示界面与计算模块单独编写。

在线体验：<https://cbb-cbb.github.io/credit-evidence-demo/>

**运行方式：合成数据 + 浏览器端透明规则，无在线大模型调用。** 作品展示数据检查、产品取舍和验证流程；不是已经商业上线的信贷产品。

## 一分钟体验

1. 默认的“渠道 C 放量”场景，比较整体逾期率、各渠道占比与渠道内部风险。
2. 点击“稳定对照”：看系统是否仍强行归因。
3. 点击“全渠道风险上升”：对比结构变化和渠道内部变化。
4. 点击“试试没有数据的9月”：看到明确的数据覆盖提示，归因规则执行0次。
5. 恢复有数据的日期，记录一条复核意见，导出 JSON 或本场景的合成 CSV。

## 问题与改进

| 体验时发现的问题 | 此 Demo 的实现 | 验收方式 |
| --- | --- | --- |
| 开始日期被旧结束日期限制，禁用原因不清楚 | 四个日期可独立修改；显示先后顺序与重叠错误 | 先修改开始日期到9月，仍可选择；运行前给出明确提示 |
| 缺数据时，最后只显示证据不足 | 分析前检查两个窗口是否有完整数据；明确说明可用日期与调整方式 | 缺9月数据、部分覆盖均拦截；规则执行0次 |
| 改描述并不改变真实输入数据 | 三个场景生成不同的确定性合成记录 | 切换场景，查看同口径指标与解释的改变 |
| 结论容易替代人的判断 | 展示证据、反证和能力限制，人工意见单独保留 | 填写理由、保存、刷新、导出 |

旧项目的8次工具调用与新 Demo 的0次归因规则检查属于不同执行机制，只用来展示“先检查数据”的设计变化，不能当作同一 Agent 的性能提升或节省百分比。

## 本地运行

Node.js 20 或更新版本，无第三方 npm 依赖，无需 `npm install`：

```powershell
npm.cmd start
```

打开 <http://127.0.0.1:5174/>。不要直接双击 HTML：JavaScript 模块需通过 HTTP 加载。

```powershell
npm.cmd test
npm.cmd run check
```

18项引擎测试已通过：确定性、3种场景、完全/部分缺数据、日期校验、加权统计、子窗口重算和数学分解。前端操作验收与限制见 [探索记录](EXPLORATION.md)。

## 实际贡献与范围

- 用户在原本地项目亲自运行3类案例、保存复核，选择保留信贷分析场景，并发现日期选择限制。
- 缺数据提示问题在协作复盘中确认；本轮由 AI 协助实现新的交互原型、生成器和测试。
- 不把生成代码等同于用户独立编程，也不把模拟演示写成前公司业务成果。
- 本 Demo 未验证真实贷款数据、真实模型准确率或商业收益，规则阈值也未经过真实数据校准。

## 文件入口

- `index.html` / `style.css` / `app.mjs`：作品页、交互、复核及导出。
- `engine.mjs`：生成数据、检查覆盖、汇总指标、执行透明规则。
- `tests/engine.test.mjs`：可重复执行的行为测试。
- [METHODS.md](METHODS.md)：生成参数、口径、阈值和数学分解。
- [EXPLORATION.md](EXPLORATION.md)：实际操作、观察、取舍、验收和待完成事项。
- [PROVENANCE.md](PROVENANCE.md)：来源与 AI 协作说明。

复核只存于当前浏览器，不会自动上传；换浏览器或清除站点存储后不会保留。可用导出文件自行保存。页面部署为静态站点，不需要服务器密钥。
